# Tools are data, executed by one interpreter

A World pack has to describe the tools an agent can call. The obvious implementation is a handler function per tool, which is what the v1 prototype had: four hardcoded Systems, twelve TypeScript functions, and a World whose collections were named fields on an object. Adding a domain meant writing code, and every new domain was a chance to reimplement ownership, validation and the Event log slightly differently.

Instead, a tool is a **declaration in `tools.yaml`** — `op` (`get`/`list`/`create`/`update`), the `collection` it acts on, an `id`/`where` selector, `lookup`s, `guards` (the Realism rules), `set`, `include` and `returns` — with `${…}` expressions over `input`, the looked-up rows, `entity` and `now`. One interpreter (`src/engine/dsl.ts`) executes every tool in every pack, behind the one Gateway. The Check vocabulary is declarative for the same reason: nine Check types over collections, fields, tool arguments and ownership, none of which names a domain concept.

Consequence: a second domain is a directory of YAML, not a pull request against the engine. `halvard-helpdesk` — a different Principal, different entities, different Systems, an Attack in a chat comment rather than an email — was added without one line of engine change, and the same test suite proves it. Ownership, injected-content detection, the World diff, the flow view's Event formatting and the MCP tool schemas all derive from the declarations, so they cannot drift per domain. It also means the DSL is now a language with a surface we must keep compatible, and anything it cannot express is a format gap rather than a quick handler — the helpdesk pack found three (an unscoped read has no row-shaped `subject`, `currency` is required outside commerce, `where` is equality-only).

Rejected: a handler function per tool with a shared helper library — it keeps the escape hatch, and an escape hatch that exists is an escape hatch that gets used, so the guarantees above become conventions. Also rejected: letting packs ship executable JavaScript, which would make an untrusted World pack an arbitrary-code-execution surface and make every pack unreviewable by the people who most need to review it.
